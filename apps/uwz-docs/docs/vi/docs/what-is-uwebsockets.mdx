µWebZockets là framework server cho Zig 0.16.0, xử lý HTTP/1.1, HTTP/2,
HTTP/3, WebSocket và JSON-RPC qua một API ứng dụng có kiểu. Nó hướng đến các
service cần bộ nhớ có giới hạn và độ trễ ổn định hơn là dung lượng co giãn.

Tên dự án xuất hiện là µWebZockets trong prose, `uWebZockets` trong đường dẫn
package và `uz` trong code Zig.

## Một ứng dụng, nhiều giao thức

Một giá trị ứng dụng sở hữu route và trạng thái transport. Cùng một chữ ký
handler phục vụ mọi phiên bản HTTP:

```zig
const std = @import("std");
const uz = @import("uWebZockets");

fn hello(_: *uz.Request, res: *uz.Response) void {
    res.text("hello") catch |err| {
        std.log.err("response failed: {}", .{err});
    };
}
```

Bạn đăng ký handler một lần và chọn transport lúc khởi động:

| Transport                        | Initializer                              | Listener         |
| -------------------------------- | ---------------------------------------- | ---------------- |
| HTTP/1.1 plaintext               | `App(N).init`                            | `listen`         |
| HTTPS với file PEM               | `init_https`                             | `listen`         |
| HTTPS với chứng chỉ trong bộ nhớ | `init_https_ephemeral`                   | `listen`         |
| HTTP/3 trên QUIC                 | `init_http3` hoặc `init_http3_ephemeral` | `listen_udp`     |
| Nhóm worker                      | `Server.builder(...).build_cluster`      | `Cluster.listen` |

Khác biệt giao thức nằm dưới ranh giới handler: lưu trữ stream HTTP/2, trạng
thái QPACK HTTP/3 và framing WebSocket thuộc về connection, còn ứng dụng nhận
dữ liệu request được mượn với vòng đời trong callback.

## Một lần cấp phát lúc khởi động

`App(N)` là kiểu dung lượng biết lúc compile cho `N` kết nối đồng thời.
Initializer của nó cấp phát một slab liền mạch chứa pool kết nối, buffer
request HTTP/1.1, vùng message WebSocket, write queue phản hồi, lưu trữ router
và scratch nén tùy chọn. Request path dùng lại các vùng đó và không cấp phát.

Thiết kế này biến dung lượng thành quyết định cấu hình thay vì bất ngờ lúc
runtime. `ServerConfig`, `Presets` và `Server.builder` biểu diễn giới hạn bằng
giá trị có tên. Khi cạn dung lượng, hệ thống trả lỗi cụ thể hoặc rejection có
cấu trúc thay vì làm queue phình ra.

## Worker shared-nothing

`App.cluster(worker_count)` và `Server.builder(...).build_cluster(...)` tạo
nhóm thread-per-core. Mỗi worker sở hữu một event loop và một slab, bind cùng
port qua `SO_REUSEPORT` ở nền tảng hỗ trợ, và chỉ phối hợp với worker khác qua
ring lock-free có giới hạn. Một kết nối nằm trọn trong worker đã accept nó.

API cluster là bổ sung. Một `App` đơn vẫn là đường ngắn nhất cho service không
cần nhiều lõi, và TLS cluster vẫn chỉ dùng TCP.

## Package cung cấp gì

| Bề mặt                            | Điểm vào công khai                  | Trạng thái             |
| --------------------------------- | ----------------------------------- | ---------------------- |
| Định tuyến và middleware HTTP/1.1 | `App`, `Request`, `Response`        | Supported              |
| HTTP/2 và HPACK                   | `init_https`, `uz.http2`            | Supported, có giới hạn |
| HTTP/3 và QPACK                   | `init_http3`, `listen_udp`          | Supported, có giới hạn |
| WebSocket server                  | `App.ws`, `uz.WebSocket`            | Supported              |
| JSON-RPC 2.0                      | `uz.json_rpc.Service`, `App.rpc`    | Supported              |
| TLS 1.3 và mTLS                   | `init_https`, `init_https_mtls`     | Supported              |
| Nhóm worker                       | `Server.builder(...).build_cluster` | Supported trên TCP     |
| C ABI                             | `include/uWebZockets.h`             | Tập con cấp cao        |
| HTTP/1.1 client                   | `uz.client`                         | Supported, có giới hạn |
| WebTransport                      | `uz.webtransport`                   | Helper-only, chưa live |

Package build BoringSSL, lsquic, libdeflate và zlib từ source được pin bằng
toolchain C và C++ của Zig. Bạn không cần CMake, zlib hệ thống hay thư viện TLS
riêng.

## Toolchain được hỗ trợ

Phiên bản 2.1.6 yêu cầu Zig 0.16.0. Linux và macOS trên `x86_64` và `aarch64`
là nền tảng runtime được hỗ trợ. Windows có job compile và runtime native;
hỗ trợ chính thức chỉ được công bố sau khi job runtime xanh cho commit phát
hành. FreeBSD, NetBSD, OpenBSD và DragonFlyBSD là target build cộng đồng,
không có CI runtime riêng.
