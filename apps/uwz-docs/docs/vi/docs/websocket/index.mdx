Một WebSocket route là HTTP route có thêm upgrade handshake và một message path
khác. µWebZockets triển khai RFC 6455, RFC 7692 per-message deflate, pub/sub có
giới hạn và RFC 8441 tunnel qua HTTP/2. Application sở hữu authentication,
origin policy và subprotocol.

Phần này bắt đầu bằng một echo route chạy được, rồi giải thích handshake, framing,
backpressure và các giới hạn vận hành quyết định một worker giữ được bao nhiêu
peer. Chương trình canonical là [chat server example](/examples/chat-server).

## Server triển khai gì

| Capability         | Status             | Chi tiết                                                                 |
| ------------------ | ------------------ | ------------------------------------------------------------------------ |
| RFC 6455 server    | Supported          | HTTP/1.1 upgrade trên `GET` route đăng ký bằng `App.ws`                  |
| RFC 7692 deflate   | Supported, opt-in  | Theo route; `server_no_context_takeover` và `client_no_context_takeover` |
| Pub/sub            | Supported          | Topic và subscription capacity cố định trong một application             |
| RFC 8441 tunnel    | Supported, bounded | Một tunnel active cho mỗi HTTP/2 connection, không deflate               |
| WebSocket client   | Not supported      | Client đi kèm chỉ nói HTTP/1.1                                           |
| Origin negotiation | Application-owned  | Đọc request header trong `upgrade` callback                              |
| Subprotocol choice | Application-owned  | Ghi `Sec-WebSocket-Protocol` khi approve upgrade                         |

Default cố ý nhỏ. `App(N)` giữ một message buffer 16 KiB cho mỗi connection và
một write queue 64 KiB cho mỗi connection; route có thể hạ frame và message limit
nhưng không được nâng quá message capacity đã cấu hình.

## Ranh giới

:::warning[Không có client hay policy layer]
µWebZockets không gửi kèm WebSocket client, origin allow list hay subprotocol
negotiation. `upgrade` callback quyết định có nhận peer hay không, và các response
helper HTTP mặc định vẫn dùng được trước khi switch.
:::
