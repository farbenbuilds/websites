WebSocket connection bắt đầu bằng một HTTP request, nên mọi mối nguy HTTP áp dụng
trước khi switch. Sau switch, framework bảo vệ parser và các bound; application
vẫn sở hữu identity, authorization, origin policy và abuse limit.

## Trust boundary

| Ranh giới            | Sở hữu bởi  | Kiểm soát                                        |
| -------------------- | ----------- | ------------------------------------------------ |
| HTTP upgrade request | Framework   | Request-line, header, body limit; strict parsing |
| Upgrade admission    | Application | `upgrade` callback, origin check, credential     |
| Frame parsing        | Framework   | Masking, opcode, UTF-8, size, close validation   |
| Nội dung message     | Application | Decode, validate, authorize từng message         |
| Fan-out              | Framework   | Queue và topic registry có giới hạn              |
| Vòng đời identity    | Application | Lưu theo connection; không có session object     |

Framework không authenticate peer, không so `Origin`, không chọn subprotocol và
không rate limit theo connection. Đó là quyết định của application với dữ liệu
của application.

## Authenticate trước switch

Browser WebSocket client gửi cookie cùng handshake. Điều đó làm cross-site
WebSocket hijacking khả thi khi server tin cookie và bỏ qua origin. Làm cả hai:

1. Validate credential trong `upgrade` callback.
2. Validate `Origin` với allow list, hoặc yêu cầu token mà page cross-site không
   đọc được.

```zig
fn admit(req: *const uz.Request) bool {
    const origin = req.get_unique_header("Origin") orelse return false;
    if (!std.mem.eql(u8, origin, "https://app.example.com")) return false;

    const authorization = req.get_unique_header("Authorization") orelse return false;
    return verify_bearer(authorization);
}
```

`get_unique_header` trả null khi header xuất hiện hai lần, nhờ đó từ chối
credential mơ hồ thay vì chọn một. Không nhận peer chỉ vì request "có vẻ nội bộ";
hãy đọc field thật.

Callback chạy đồng bộ trên worker thread. Một round trip database thuộc về HTTP
route phát hành ticket ngắn hạn, không thuộc callback.

## Giới hạn mọi tài nguyên

| Tài nguyên            | Kiểm soát                             | Default      |
| --------------------- | ------------------------------------- | ------------ |
| Message size          | `max_message_size` trên route         | 16 KiB       |
| Frame size            | `max_frame_size` trên route           | 16 KiB       |
| Output đang chờ       | `write_queue_size`                    | 64 KiB       |
| Connection im lặng    | `idle_timeout_ms`                     | 120 s        |
| Heartbeat             | `ping_interval_ms`, `pong_timeout_ms` | tắt          |
| Topic và subscription | Registry capacity cố định             | 1024 / 8192  |
| Connection            | `App(N)` hoặc `with_max_clients`      | compile-time |

Route không được nâng `max_message_size` quá message capacity đã cấu hình. Nếu cần
message lớn hơn, tăng capacity và chấp nhận chi phí slab cho mọi connection.

## Rate limit theo connection và worker

Middleware rate limit có sẵn bảo vệ HTTP route. WebSocket route cần counter riêng
vì không có request boundary. Giữ counter trong application storage khóa theo
socket, reset theo cửa sổ cố định, và close peer với `1008 Policy violation` khi
vượt budget.

Counter per-worker không thấy peer ở worker khác. Khi budget toàn cục quan trọng,
dùng external store dùng chung và chấp nhận latency, hoặc shard budget theo worker
và ghi rõ hệ số nhân.

## Compression side channel

Nén rò rỉ độ dài message. Nếu peer ảnh hưởng được byte được nén cạnh secret trong
cùng context, nó có thể học về secret. µWebZockets nén theo từng message với
no-context-takeover, loại bỏ state xuyên message nhưng vẫn giữ tín hiệu độ dài
theo message.

Tắt nén trên route mang token và không bao giờ echo secret. Xem
[per-message deflate](/docs/websocket/compression).

## TLS và proxy

- Phục vụ `wss://` trong production. Upgrade plaintext lộ cookie và nội dung
  message cho mọi hop.
- Reverse proxy phải forward `Upgrade` và `Connection` và không buffer connection
  đã upgrade.
- Đặt proxy read timeout dài hơn heartbeat interval, nếu không proxy bỏ peer im
  lặng trước khi heartbeat kịp hành động.
- Forward địa chỉ client trong header bạn chỉ tin từ proxy. Không rate limit theo
  header client có thể giả mạo.

ALPN và certificate policy nằm trong phần TLS. Bắt đầu với
[ephemeral certificate](/examples/first-tls-server) cho công việc cục bộ.

## Logging

Log route, close code và reason có giới hạn. Không log message body, token, cookie
hay toàn bộ header; development log ghi một dòng HTTP cho mỗi exchange và độ dài
message cho mỗi WebSocket message, không ghi payload.
