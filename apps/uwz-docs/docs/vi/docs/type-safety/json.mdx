JSON đi qua hai typed boundary: request body thành Zig value, và Zig value thành
response byte. Allocator và output buffer luôn tường minh, nên handler có thể nêu
memory bound tại call site.

## Decode body request

```zig
const std = @import("std");
const uz = @import("uWebZockets");

const Note = struct {
    text: []const u8,
};

fn create(req: *uz.Request, res: *uz.Response) void {
    const parsed = req.json(Note, std.heap.page_allocator) catch |err| {
        std.log.warn("json parse failed: {}", .{err});
        res.end_best_effort("400 Bad Request", "invalid json");
        return;
    };
    defer parsed.deinit();

    var buffer: [256]u8 = undefined;
    res.json_buf(.{ .ok = true, .text = parsed.value.text }, &buffer) catch |err| {
        std.log.err("json response failed: {}", .{err});
    };
}
```

`req.json(T, allocator)` trả `std.json.Parsed(T)`. Allocator sở hữu value đã
decode, gồm string và array lồng nhau. Gọi `deinit` đúng một lần; không free từng
field.

`Request.json` không kiểm tra `Content-Type`. Nó parse byte body bất kể media type.
Kiểm tra media type trước khi route chấp nhận nhiều hơn JSON.

## Phương thức response

| Method                              | Storage                                          | Failure                                                                         |
| ----------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------- |
| `res.json(value, allocator)`        | Render tạm bằng allocator, free trước khi trả về | `OutOfMemory` khi render; `WouldBlock` hoặc `ResponseAlreadyStarted` khi gửi    |
| `res.json_buf(value, buffer)`       | Buffer của caller                                | `BufferOverflow` khi render; `WouldBlock` hoặc `ResponseAlreadyStarted` khi gửi |
| `res.json_value(value, allocator)`  | Như `json` cho `std.json.Value`                  | Như `json`                                                                      |
| `res.json_value_buf(value, buffer)` | Như `json_buf` cho `std.json.Value`              | Như `json_buf`                                                                  |
| `res.begin_json()`                  | Fixed stack coalescing buffer                    | `ResponseAlreadyStarted`; stream write báo `WriteFailed`                        |

Cả bốn method cố định gửi `200 OK` với
`Content-Type: application/json; charset=utf-8`. `json` và `json_buf` nhận mọi
type mà `std.json.Stringify` hỗ trợ. Biến thể `json_value` nhận
`std.json.Value` động.

`json` chỉ allocate phần render tạm. Nó free buffer đó trước khi helper trả về, và
response queue sở hữu bản copy byte của mình. Allocator bạn truyền không bị đụng
tới.

Fixed body được render và queue trong một bước. Trên HTTP/1.1, nếu body đã render
không vừa write queue, `json` trả `error.WouldBlock`. Dùng `begin_json` khi
document có thể vượt queue.

## Validate trong lúc decode

`req.validate_json(T, allocator)` parse body và áp rule trong `T.validation`.
`req.validate_json_detailed(T, allocator, &issue)` báo field và constraint bị từ
chối đầu tiên.

```zig
var issue = uz.schema.Issue{};

const parsed = req.validate_json_detailed(CreateUser, std.heap.page_allocator, &issue) catch |err| {
    if (err == error.ConstraintViolation or err == error.MalformedJson) {
        res.end_best_effort("422 Unprocessable Entity", @tagName(issue.kind));
        return;
    }
    res.end_best_effort("500 Internal Server Error", "validation failed");
    return;
};
defer parsed.deinit();
```

`ConstraintViolation` nghĩa là rule đã khai báo từ chối value. `MalformedJson`
nghĩa là parse fail trước khi rule chạy. Allocation failure là
`error.OutOfMemory`. Xem [Schema validation](/docs/type-safety/schema-validation)
cho field rule và issue kind.

## Stream response lớn

`begin_json()` stream một JSON response chunked qua stack buffer cố định. Xem
[JSON response](/docs/http/json#streaming-responses) cho các stream method và
backpressure behavior.

## Giới hạn kích thước

Request body bị giới hạn bởi `ServerConfig.max_body_size`; `json_buf` bị giới hạn
bởi buffer của caller; response cố định bị giới hạn bởi HTTP/1.1 write queue. Xem
[JSON response](/docs/http/json#size-limits) cho bảng đầy đủ và failure mapping.

## Quy tắc ownership

| Value                        | Owner                           | Lifetime                   |
| ---------------------------- | ------------------------------- | -------------------------- |
| `Parsed(T)`                  | Allocator truyền cho `req.json` | Đến `deinit`               |
| `req.text()` / `req.bytes()` | Connection request              | Handler callback           |
| `json_buf` buffer            | Caller                          | Call; queue copy byte      |
| `res.json` temporary render  | Allocator                       | Free trước khi call trả về |
| `JsonStream`                 | Caller                          | Đến `end`; giữ ổn định     |

Không lưu request slice sau khi handler trả về. Copy nó bằng cùng allocator tường
minh khi nó phải sống lâu hơn request.
