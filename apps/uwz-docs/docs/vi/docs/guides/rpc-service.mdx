Typed procedure là đường ngắn nhất từ một Zig struct đến một JSON-RPC method.
Hướng dẫn này đăng ký hai, mount service trên một HTTP route và kiểm chứng bằng curl.

## Bài toán

Bạn có những operation cần method có tên, shape request/response và error có cấu
trúc, và bạn không muốn tự viết JSON dispatch cho từng cái.

## Giả định

- Project Zig 0.16.0 của bạn đã phụ thuộc µWebZockets.
- Method name là định danh public ổn định, được copy lúc đăng ký.
- Parameter vừa scratch 4 KiB; document lớn hơn dùng API `register` với allocator
  tường minh, xem [typed procedures](/docs/json-rpc/typed-procedures).

## Build service

```zig src/main.zig
const std = @import("std");
const uz = @import("uWebZockets");

const AddParams = struct { left: i64, right: i64 };
const AddResult = struct { sum: i64 };
const DivideParams = struct { numerator: i64, denominator: i64 };
const DivideResult = struct { quotient: i64 };

fn add(params: AddParams) uz.json_rpc.HandlerError!AddResult {
    return .{ .sum = params.left + params.right };
}

fn divide(params: DivideParams) uz.json_rpc.HandlerError!DivideResult {
    if (params.denominator == 0) return error.InvalidParams;
    return .{ .quotient = @divTrunc(params.numerator, params.denominator) };
}

pub fn main(init: std.process.Init) !void {
    var app = try uz.App(128).init(init.io);
    defer app.deinit();

    var rpc = uz.json_rpc.Service{};
    try rpc.register_typed("math.add", AddParams, AddResult, add);
    try rpc.register_typed("math.divide", DivideParams, DivideResult, divide);
    _ = try app.rpc("/rpc", &rpc);

    try app.catch_shutdown_signals();
    try app.listen("127.0.0.1", 3000);
    try app.run();
}
```

`app.rpc` đăng ký `POST /rpc`, seal registry và lưu pointer tới service. Giữ
service sống suốt thời gian run: nó sở hữu một response buffer và thuộc một event
loop. `service.response_buffer()` mở buffer đó khi bạn dispatch thủ công.

## Error và batch

Procedure fault vẫn là HTTP `200` với object `error`; chỉ transport failure mới
dùng status khác.

| Bạn trả về              | Kết quả JSON-RPC           | HTTP |
| ----------------------- | -------------------------- | ---- |
| Một result value        | Member `result`            | 200  |
| `error.InvalidParams`   | `-32602 Invalid params`    | 200  |
| `call.fail(code, text)` | Code `-32000` đến `-32099` | 200  |
| Notification (không id) | Không body                 | 204  |

Batch được parse như một JSON document hoàn chỉnh trước khi procedure đầu tiên
chạy, nên syntax error ở phần tử cuối dừng cả batch. Semantic error ở một phần tử
không dừng các phần tử còn lại. Xem [JSON-RPC errors](/docs/json-rpc/errors) và
[batches và notifications](/docs/json-rpc/batches-and-notifications).

## Giả định capacity

| Tài nguyên              | Mặc định               | Triệu chứng khi cạn                    |
| ----------------------- | ---------------------- | -------------------------------------- |
| Procedure               | 64 mỗi service         | `error.ProcedureCapacityReached`       |
| Method name được copy   | 4 KiB mỗi service      | `error.MethodStorageCapacityReached`   |
| Response document       | 16 KiB mỗi service     | `-32603`, hoặc HTTP `500` khi body lớn |
| Typed parameter scratch | 4 KiB stack            | `-32603 Internal error` khi tràn       |
| Request body            | 16 KiB `max_body_size` | `413 Payload Too Large` trước dispatch |

Tăng hai mục đầu bằng `uz.json_rpc.configured_service`, hàm nhận số procedure,
method storage byte và response byte.

## Hành vi khi lỗi

| Điều kiện                     | Kết quả                                       |
| ----------------------------- | --------------------------------------------- |
| Method không tồn tại          | `200` với `-32601 Method not found`           |
| `params` thiếu hoặc sai type  | `200` với `-32602 Invalid params`             |
| `Content-Type` sai hoặc trùng | `415 Unsupported Media Type`, body rỗng       |
| Result lớn hơn response       | `-32603`, hoặc `500` khi error cũng không vừa |
| Đăng ký sau khi mount         | `error.RegistryLocked` lúc startup            |

## Kiểm chứng

```sh
curl -sS http://127.0.0.1:3000/rpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","method":"math.add","params":{"left":2,"right":3},"id":1}' \
  | jq -e '.result.sum == 5'
```

```sh
curl -sS http://127.0.0.1:3000/rpc \
  -H 'Content-Type: application/json' \
  --data '[{"jsonrpc":"2.0","method":"math.add","params":{"left":4,"right":5},"id":3},
           {"jsonrpc":"2.0","method":"math.add","params":{"left":6,"right":7}}]'
```

Command đầu thoát khác 0 nếu sum không phải `5`. Batch trả array một phần tử:
notification đã chạy nhưng không tạo response. Gửi `math.divide` với
`"denominator":0` và response mang `-32602`.

## Biến thể: mang context

`register_typed_context` truyền mutable pointer tới state có type. Context phải là
mutable single-item pointer; truyền value hoặc const pointer là compile error.

```zig
const Ledger = struct { calls: u64 = 0 };

fn transfer(context: *Ledger, params: AddParams) uz.json_rpc.HandlerError!AddResult {
    context.calls += 1;
    return .{ .sum = params.left + params.right + context.calls };
}

var ledger = Ledger{};
try rpc.register_typed_context("math.counted_add", &ledger, AddParams, AddResult, transfer);
```

Trong cluster, tạo một ledger cho mỗi worker. Pointer không được chia sẻ giữa các
event loop.

## Biến thể: dispatch lúc compile

`comptime_service` build jump table cố định. Nó không có `register` hay `seal`, nên
`app.rpc` từ chối lúc compile; mount bằng cách tự gọi `dispatch`.

```zig
fn add_raw(call: *uz.json_rpc.Call) uz.json_rpc.HandlerError!void {
    var parse_buffer: [4 * 1024]u8 = undefined;
    var parse_allocator = std.heap.FixedBufferAllocator.init(&parse_buffer);
    const parsed = try call.parse_params(AddParams, parse_allocator.allocator());
    defer parsed.deinit();
    try call.result(.{ .sum = parsed.value.left + parsed.value.right });
}

const procedures = [_]uz.json_rpc.StaticProcedure{
    .{ .method = "math.add", .handler = add_raw },
};
const StaticRpc = uz.json_rpc.comptime_service(&procedures);
var rpc = StaticRpc{};

fn rpc_route(req: *uz.Request, res: *uz.Response) void {
    const document = rpc.dispatch(req.bytes(), rpc.response_buffer()) catch {
        res.end("500 Internal Server Error", "") catch {};
        return;
    };
    const body = document orelse {
        res.end("204 No Content", "") catch {};
        return;
    };
    res.end_with_headers("200 OK", "Content-Type: application/json\r\n", body) catch {};
}
```
