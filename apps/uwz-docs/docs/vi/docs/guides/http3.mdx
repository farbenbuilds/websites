HTTP/3 là UDP listener với TLS context riêng. Request và response API không
đổi; transport policy, capacity và ranh giới cluster thì có.

## Vấn đề

Bạn cần QUIC endpoint phục vụ cùng route với HTTP server, và cần biết guarantee
nào không đi kèm từ TCP.

## Giả định

- Có Zig 0.16.0 và `curl` build với HTTP/3.
- Server sở hữu UDP port 8443 và không gì khác bind port đó.
- QUIC vẫn single-application. Không có HTTP/3 cluster.
- HTTP/3 early data bị từ chối; mọi request đợi handshake.

## Viết chương trình

```zig src/main.zig
const std = @import("std");
const uz = @import("uWebZockets");

fn index(_: *uz.Request, res: *uz.Response) void {
    res.end_with_headers(
        "200 OK",
        "Content-Type: text/plain\r\n",
        "Hello from bounded HTTP/3",
    ) catch |err| std.log.err("response failed: {}", .{err});
}

pub fn main(init: std.process.Init) !void {
    var app = try uz.App(128).init_http3_ephemeral(init.io);
    defer app.deinit();

    _ = try app.get("/", index);
    try app.listen_udp("0.0.0.0", 8443);
    try app.catch_shutdown_signals();
    try app.run();
}
```

`init_http3_ephemeral` tạo hai context: TCP chào `h2` và `http/1.1`, còn QUIC chỉ
chào `h3`. Chương trình này chỉ bind UDP transport. Certificate được tạo trong
memory và client không tin.

## Kiểm tra

```sh
zig build run
```

```sh
curl --http3 -k https://127.0.0.1:8443/
```

```console
Hello from bounded HTTP/3
```

`-k` cần cho certificate sinh tự động. Nếu `curl` không có HTTP/3, lệnh fail
trước khi tới server; kiểm tra `curl --version` có `HTTP3`. Dùng QUIC client như
ngtcp2 hoặc quiche khi `curl` không đàm phán được `h3`.

## Ranh giới

| Surface            | Hành vi HTTP/3                                    |
| ------------------ | ------------------------------------------------- |
| Cluster            | Không hỗ trợ; `listen_udp` là single-application  |
| 0-RTT              | Bị từ chối trên listener                          |
| WebTransport       | Extended CONNECT trả `501 Not Implemented`        |
| Metrics registry   | Ghi request record, không tăng counter            |
| Request header     | `max_header_size` tối đa 65535 byte               |
| Request body       | `max_h3_body_size`                                |
| Congestion control | BBRv1 với pacing per connection, không cấu hình   |
| Receive batching   | `UDP_GRO` tắt; transmit batching theo packet size |

QPACK decoder, packet buffer, stream state và body lấy từ pool cấp lúc startup.
Listener kiểm tra thứ tự pseudo-field và từ chối connection-specific field bằng
`H3_MESSAGE_ERROR` theo stream.

## Giả định capacity

| Tài nguyên      | Giới hạn                             | Hệ quả                            |
| --------------- | ------------------------------------ | --------------------------------- |
| QUIC connection | Connection capacity đã cấu hình      | Handshake dư bị drop              |
| Active stream   | Có bound mỗi connection              | Write bị từ chối trả `WouldBlock` |
| Header block    | `max_header_size`, tối đa 65535 byte | Block lớn hơn bị từ chối          |
| UDP payload     | 2 KiB                                | Response lớn bị chia packet       |
| Pool            | Cấp bởi `listen_udp`                 | Tồn tại đến `deinit`              |

Một `App` sở hữu QUIC pool. Không hỗ trợ dùng lại process cho UDP listener thứ
hai, nên size transport duy nhất cho peak connection.

## Hành vi khi lỗi

| Điều kiện                  | Kết quả                          |
| -------------------------- | -------------------------------- |
| UDP port đã bị bind        | `listen_udp` trả IO error        |
| Client không có `h3`       | Handshake fail, không có request |
| Request 0-RTT              | Bị từ chối trước handler         |
| WebTransport CONNECT       | `501 Not Implemented`            |
| Header block vượt giới hạn | Request bị từ chối               |
| Certificate mismatch       | `init_http3` fail lúc startup    |

## Biến thể

### Certificate production

```zig
var app = try uz.App(128).init_http3(
    init.io,
    "certs/fullchain.pem",
    "certs/privkey.pem",
);
defer app.deinit();
```

`init_http3` load cùng cặp vào TCP và QUIC context. QUIC context vẫn chỉ chào
`h3` và giữ early data tắt. Cặp được kiểm tra lúc load, nên mismatch fail trước
khi listener start.

### Giữ listener chỉ UDP

QUIC cần đường UDP end to end. TCP reverse proxy trước process không forward
được QUIC trừ khi cũng relay UDP, nên hoặc pass UDP through, hoặc terminate
HTTP/3 ở edge và forward HTTP/1.1 hoặc HTTP/2 vào application:

```sh
ss -lunp | grep 8443
```

```console
UNCONN 0 0 0.0.0.0:8443 0.0.0.0:* users:(("your-app",pid=4242,fd=7))
```

Không có TCP socket cho port đó. Giữ health check và metrics trên TCP listener
hoặc edge, vì process chỉ UDP không có HTTP/1.1 probe surface.
