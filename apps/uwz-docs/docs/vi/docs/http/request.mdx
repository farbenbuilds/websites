`Request` là snapshot dạng mượn của một HTTP request. Các field trỏ vào
buffer request của connection, nên đọc không cấp phát. Dùng các accessor bên
dưới thay vì truy cập trực tiếp mảng header inline.

## Field của request

| Field      | Nội dung                                                     |
| ---------- | ------------------------------------------------------------ |
| `method`   | Method token viết hoa, ví dụ `GET` hoặc `POST`               |
| `target`   | Request target gốc, gồm cả query                             |
| `path`     | Path không có query                                          |
| `query`    | Byte query không có dấu `?` ở đầu                            |
| `body`     | Request body đầy đủ và có giới hạn                           |
| `protocol` | Protocol token của extended `CONNECT`, khi được thương lượng |

`url()` trả về đúng các byte đã mượn như `target`. Hàm không tự tạo scheme
hay authority và không giải mã percent escape.

## Truy cập header

| Method                          | Trả về           | Hành vi                                           |
| ------------------------------- | ---------------- | ------------------------------------------------- |
| `get_header(name)`              | `?[]const u8`    | Field khớp đầu tiên, không phân biệt hoa thường   |
| `get_unique_header(name)`       | `?[]const u8`    | Chỉ trả về khi đúng một field khớp                |
| `count_headers(name)`           | `usize`          | Số field khớp                                     |
| `header_has_token(name, token)` | `bool`           | So khớp token trong field phân tách bằng dấu phẩy |
| `has_header(name)`              | `bool`           | Tương đương `get_header(name) != null`            |
| `headers()`                     | `HeadersView`    | View có `get`, `has` và `entries`                 |
| `header_entries()`              | `HeaderIterator` | Iterator qua các entry `{ name, value }`          |

Tên field không phân biệt hoa thường theo ASCII. Field lặp lại giữ nguyên thứ
tự xuất hiện và không được ghép lại. `get_unique_header` là accessor đúng cho
field đơn như `Content-Type` và `Authorization`; field bị lặp trả về `null`
thay vì một giá trị đầu tiên tùy ý.

```zig
fn inspect(req: *uz.Request, res: *uz.Response) void {
    const request_id = req.get_unique_header("x-request-id") orelse "anonymous";
    const trace_count = req.count_headers("x-trace");
    const wants_json = req.header_has_token("accept", "application/json");

    var entries = req.header_entries();
    while (entries.next()) |entry| {
        std.debug.print("{s}: {s}\n", .{ entry.name, entry.value });
    }

    var buffer: [128]u8 = undefined;
    const body = std.fmt.bufPrint(
        &buffer,
        "{s} {d} {}",
        .{ request_id, trace_count, wants_json },
    ) catch return;
    res.text(body) catch {};
}
```

## Capacity của header và capture

| Lưu trữ              | Mặc định                | Capacity bổ sung                |
| -------------------- | ----------------------- | ------------------------------- |
| Field header inline  | 64 (`max_headers`)      | `with_max_header_count` trên 64 |
| Route capture inline | 16 (`max_route_params`) | `with_max_route_params` trên 16 |

Transport mượn một cặp slice name/value bổ sung cho mỗi connection và dùng lại
qua các request trên connection đó. Cấu hình trên mức inline đặt các slice này
vào slab của từng connection, nên request vẫn không cấp phát. `add_header` và
`add_param` điền mảng inline trước, rồi đến capacity bổ sung, và fail closed
với `HeaderCapacityReached` hoặc `RouteParameterCapacityReached` khi hết chỗ.

Số header mặc định là 64. Trên HTTP/1.1, request có nhiều field header hơn sẽ
nhận `431 Request Header Fields Too Large` trừ khi server dành thêm slot;
HTTP/2 từ chối header list vượt capacity bằng connection error. Giới hạn body
mặc định là 16 KiB và body HTTP/1.1 quá lớn nhận `413 Payload Too Large`. Xem
[giới hạn HTTP](/docs/http/limits) để có bảng đầy đủ.

## Truy cập body

| Method                                        | Trả về                | Ghi chú                                |
| --------------------------------------------- | --------------------- | -------------------------------------- |
| `text()`                                      | `[]const u8`          | Byte body dạng text, không đổi charset |
| `bytes()`                                     | `[]const u8`          | Đúng các byte body đã mượn             |
| `json(T, allocator)`                          | `!std.json.Parsed(T)` | Parse toàn bộ body; gọi `deinit()`     |
| `validate_json(T, allocator)`                 | `!std.json.Parsed(T)` | Áp dụng rule `validation` lúc compile  |
| `validate_json_detailed(T, allocator, issue)` | `!std.json.Parsed(T)` | Ghi issue đầu tiên của field           |

Body luôn đầy đủ và có giới hạn. API này không mở request body dạng stream.
`text()` và `bytes()` trả về trực tiếp buffer; hàm không copy và không kiểm
tra UTF-8.

```zig
const CreateUser = struct {
    name: []const u8,
};

fn create(req: *uz.Request, res: *uz.Response) void {
    const parsed = req.json(CreateUser, std.heap.page_allocator) catch {
        res.end("400 Bad Request", "invalid json") catch {};
        return;
    };
    defer parsed.deinit();

    var buffer: [128]u8 = undefined;
    const body = std.fmt.bufPrint(&buffer, "created {s}", .{parsed.value.name}) catch return;
    res.end("201 Created", body) catch {};
}
```

`validate_json` đọc khai báo `pub const validation` trên `T`. Biến thể detailed
ghi field bị từ chối đầu tiên và `IssueKind` của nó vào `Issue` do caller sở
hữu.

## Query, form, multipart và cookie

| Method                        | Trả về              | Hành vi                                      |
| ----------------------------- | ------------------- | -------------------------------------------- |
| `query_params()`              | `!QueryParams`      | View query zero-copy với 32 slot cặp         |
| `query_params_of(N)`          | `!QueryParamsOf(N)` | View tương tự với capacity lúc compile       |
| `form()`                      | `!QueryParams`      | Yêu cầu form content type và parse body      |
| `multipart()`                 | `!multipart.Parser` | Yêu cầu `Content-Type` multipart duy nhất    |
| `cookie(name)`                | `?[]const u8`       | Cặp RFC 6265 đầu tiên qua mọi field `Cookie` |
| `signed_cookie(name, secret)` | `!?[]const u8`      | Xác minh giá trị ký HMAC-SHA256              |
| `accepts(media_type)`         | `bool`              | Kiểm tra field `Accept` đầu tiên             |

Key và value của query mượn request target; percent escape vẫn ở dạng encode
cho đến khi bạn giải mã. Form parse kiểm tra media type trước khi đọc body.
Multipart boundary dài hơn 70 byte fail với `InvalidMultipartBoundary`. Thiếu
`Content-Type` cho `form` hoặc `multipart` trả về `MissingContentType`. View
vượt capacity trả về `TooManyQueryParameters`, và `form` từ chối media type
không phải form bằng `UnsupportedMediaType`.

`accepts` coi field `Accept` thiếu hoặc không parse được là `*/*`. Nếu signed
cookie tồn tại và secret ngắn hơn 32 byte, hàm trả về `CookieSecretTooShort`;
chữ ký sai hoặc malformed trả về `InvalidCookieSignature`. Ký chỉ chứng minh
tính toàn vẹn, không phải mã hóa.

```zig
fn search(req: *uz.Request, res: *uz.Response) void {
    const params = req.query_params() catch return;
    const page = (params.get_int(u32, "page") catch null) orelse 1;
    const query = params.get("q") orelse "";

    const secret = "0123456789abcdef0123456789abcdef";
    const session = req.signed_cookie("session", secret) catch null;
    if (session == null) {
        res.redirect("/login", 303) catch {};
        return;
    }

    var buffer: [160]u8 = undefined;
    const body = std.fmt.bufPrint(&buffer, "page {d}: {s}", .{ page, query }) catch return;
    res.text(body) catch {};
}
```

## Route capture và lifetime

| Method                  | Trả về          | Hành vi                                          |
| ----------------------- | --------------- | ------------------------------------------------ |
| `get_param(name)`       | `?[]const u8`   | Tra capture khớp chính xác, phân biệt hoa thường |
| `clone(allocator)`      | `!OwnedRequest` | Copy mọi field, header và capture                |
| `OwnedRequest.view()`   | `*Request`      | View ổn định của request đã copy                 |
| `OwnedRequest.deinit()` | `void`          | Giải phóng snapshot                              |

`get_param` đọc capture `:name` và `*name` ở cuối. Tên được so khớp chính xác;
value được mượn. Trang [route parameter](/docs/http/route-parameters) trình
bày cú pháp pattern và thứ tự ưu tiên.

Mọi field, header value và capture đều mượn buffer của connection. Chúng còn
hợp lệ trong handler đồng bộ hoặc đến khi async response hoàn tất. Không giữ
slice thô cho công việc sau đó. `clone` copy request vào vùng nhớ do allocator
sở hữu; `view()` còn hợp lệ đến `deinit`, và snapshot lỗi trả về
`RequestSnapshotTooLarge`.

```zig
fn snapshot(req: *uz.Request, allocator: std.mem.Allocator) !uz.OwnedRequest {
    return req.clone(allocator);
}
```

Caller sở hữu snapshot trả về, phải gọi `deinit` đúng một lần và không dùng
`view()` sau lần gọi đó. Xem [ownership và
lifetime](/docs/concepts/ownership-and-lifetimes) để hiểu toàn bộ quy tắc.

## Kiểm tra

```sh
curl -i 'http://127.0.0.1:3000/search?page=2&q=slab' -H 'X-Request-Id: demo'
```

Với handler query bên trên, request này không có cookie `session`, nên response
là `303 See Other` với `Location: /login`. Signed cookie hợp lệ sẽ nhận body
`page 2: slab`.
