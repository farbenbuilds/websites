Each page documents one canonical program from the framework `examples/`
directory. The page gives the complete source, the consumer `build.zig` wiring,
the run command, the expected output, the capacities the example chooses, and
one variation worth trying.

These pages are not a substitute for the task tutorials. Start with
[Your first HTTP server](/docs/examples/first-http-server) when you are learning
the lifecycle, and use an example page when you want the exact program that the
framework ships.

## Run an example in your project

<Steps>
  <Step title="Add the dependency">
    ```sh
    zig fetch --save 'https://github.com/farbenbuilds/uWebZockets/archive/refs/tags/v2.1.6.tar.gz'
    ```
  </Step>
  <Step title="Wire the module">
    ```zig build.zig
    const std = @import("std");

    pub fn build(b: *std.Build) void {
        const target = b.standardTargetOptions(.{});
        const optimize = b.standardOptimizeOption(.{});
        const uz = b.dependency("uWebZockets", .{
            .target = target,
            .optimize = optimize,
        });

        const exe = b.addExecutable(.{
            .name = "example",
            .root_module = b.createModule(.{
                .root_source_file = b.path("src/main.zig"),
                .target = target,
                .optimize = optimize,
            }),
        });
        exe.root_module.addImport("uWebZockets", uz.module("uWebZockets"));
        b.installArtifact(exe);

        const run = b.addRunArtifact(exe);
        b.step("run", "Run the example").dependOn(&run.step);
    }
    ```

  </Step>
  <Step title="Copy the program">
    Copy the page source into `src/main.zig`. The full source link on each page
    points at the framework file the page mirrors.
  </Step>
  <Step title="Build and run">
    ```sh
    zig build run
    ```
  </Step>
  <Step title="Verify">
    Use the `curl` or `wscat` command on the example page. The TLS cluster and
    HTTP/3 examples install the signal watcher and drain on Ctrl+C; the other
    examples terminate immediately.
  </Step>
</Steps>

## Upstream build steps

The framework repository also exposes each program as a named build step, such
as `zig build hello_world` or `zig build tls_cluster`. Those commands run inside
a framework checkout and are contributor shortcuts; they are not the consumer
path. In your project, use `zig build run` after copying the source.
