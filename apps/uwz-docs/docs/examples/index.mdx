### Before you start [#before-you-start]

Complete [Installation](/docs/getting-started/installation) and
[Quickstart](/docs/getting-started/quickstart) first. The examples assume:

- Zig 0.16.0 is installed from [ziglang.org/download](https://ziglang.org/download/).
- Your project already depends on `uWebZockets` version 2.1.6.
- `src/main.zig` contains the program you want to run.
- `zig build run` starts the project.

## Canonical programs [#canonical-programs]

Each page documents one program from the framework `examples/` directory. It
gives the complete source, the consumer `build.zig` wiring, the run command, the
expected output, the capacities the example chooses, and one variation. Start
with [Hello world](/examples/hello-world), which also carries the first HTTP
tutorial; the table lists the larger programs.

| Example                                                    | Shows                                            | Protocol                | Default port |
| ---------------------------------------------------------- | ------------------------------------------------ | ----------------------- | -----------: |
| [HTTPS server](/examples/https-server)                     | In-memory TLS certificate and ALPN               | HTTPS, HTTP/1.1, HTTP/2 |         3443 |
| [Shared-nothing cluster](/examples/shared-nothing-cluster) | Four workers, one slab and loop each             | HTTP/1.1                |         3000 |
| [TLS cluster](/examples/tls-cluster)                       | Per-worker TLS contexts and runtime worker count | HTTPS, HTTP/1.1, HTTP/2 |         8443 |
| [Basic microservice](/examples/basic-microservice)         | `Presets.microservice`, JSON, query parsing      | HTTP/1.1                |         3000 |
| [Custom builder](/examples/custom-builder)                 | Fluent capacities and `slab_bytes()`             | HTTP/1.1                |         3001 |

## Run an example in your project [#run-an-example-in-your-project]

<Steps>
  <Step title="Add the dependency">
    ```sh
    zig fetch --save 'https://github.com/farbenbuilds/uWebZockets/archive/refs/tags/v2.1.6.tar.gz'
    ```
  </Step>
  <Step title="Wire the module">
    ```zig build.zig
    const std = @import("std");

    pub fn build(b: *std.Build) void {
        const target = b.standardTargetOptions(.{});
        const optimize = b.standardOptimizeOption(.{});
        const uz = b.dependency("uWebZockets", .{
            .target = target,
            .optimize = optimize,
        });

        const exe = b.addExecutable(.{
            .name = "example",
            .root_module = b.createModule(.{
                .root_source_file = b.path("src/main.zig"),
                .target = target,
                .optimize = optimize,
            }),
        });
        exe.root_module.addImport("uWebZockets", uz.module("uWebZockets"));
        b.installArtifact(exe);

        const run = b.addRunArtifact(exe);
        b.step("run", "Run the example").dependOn(&run.step);
    }
    ```

  </Step>
  <Step title="Copy the program">
    Copy the page source into `src/main.zig`. The full source link on each
    canonical page points at the framework file the page mirrors.
  </Step>
  <Step title="Build and run">
    ```sh
    zig build run
    ```
  </Step>
  <Step title="Verify">
    Use the `curl` or `wscat` command on the example page. The TLS cluster and
    HTTP/3 examples install the signal watcher and drain on Ctrl+C; the other
    examples terminate immediately.
  </Step>
</Steps>

## Upstream build steps [#upstream-build-steps]

The framework repository also exposes each canonical program as a named build
step, such as `zig build hello_world` or `zig build tls_cluster`. Those commands
run inside a framework checkout and are contributor shortcuts; they are not the
consumer path. In your project, use `zig build run` after copying the source.
