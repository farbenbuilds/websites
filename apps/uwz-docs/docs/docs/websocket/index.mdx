A WebSocket route is an HTTP route with an upgrade handshake and a different
message path. µWebZockets implements RFC 6455, RFC 7692 per-message deflate, a
bounded pub/sub registry, and RFC 8441 tunneling over HTTP/2. The application
owns authentication, origin policy, and subprotocol selection.

The section starts with a working echo route, then explains the handshake,
framing, backpressure, and the operational limits that decide how many peers one
worker can hold. The canonical program is the
[chat server example](/examples/chat-server).

## What the server implements

| Capability         | Status             | Detail                                                                   |
| ------------------ | ------------------ | ------------------------------------------------------------------------ |
| RFC 6455 server    | Supported          | HTTP/1.1 upgrade on a `GET` route registered with `App.ws`               |
| RFC 7692 deflate   | Supported, opt-in  | Per route; `server_no_context_takeover` and `client_no_context_takeover` |
| Pub/sub            | Supported          | Fixed topic and subscription capacity inside one application             |
| RFC 8441 tunnel    | Supported, bounded | One active tunnel per HTTP/2 connection, no deflate                      |
| WebSocket client   | Not supported      | The bundled client speaks HTTP/1.1 only                                  |
| Origin negotiation | Application-owned  | Read the request headers in the `upgrade` callback                       |
| Subprotocol choice | Application-owned  | Write `Sec-WebSocket-Protocol` on an approved upgrade                    |

The defaults are small on purpose. `App(N)` reserves one 16 KiB message buffer
per connection and a 64 KiB write queue per connection; a route may lower its
frame and message limits but may not raise them above the configured message
capacity.

## Boundaries

:::warning[No built-in client or policy layer]
µWebZockets does not ship a WebSocket client, an origin allow list, or
subprotocol negotiation. The `upgrade` callback decides whether to accept a
peer, and the default HTTP response helpers are available before the switch.
:::
