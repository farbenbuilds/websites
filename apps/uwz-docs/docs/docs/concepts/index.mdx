The concepts section explains how one application value becomes bounded runtime
behavior. Read it before the protocol pages. Each protocol page links back here
instead of repeating the model.

The first six pages cover the pieces of the request path: application
construction, request parsing, response completion, route matching, handler
shapes, and middleware. The later pages cover the memory, concurrency, and
failure boundaries behind that path.

## Where to start

If you are choosing limits, read [Application model](/docs/concepts/application-model)
and [Capacity model](/docs/concepts/capacity-model) first. If you are writing a
handler, read [Request lifecycle](/docs/concepts/request-lifecycle) and
[Handler shapes](/docs/concepts/handler-shapes). If you are adding policy that
applies to many routes, read [Middleware model](/docs/concepts/middleware-model).
