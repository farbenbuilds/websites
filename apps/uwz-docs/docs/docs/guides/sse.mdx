Server-Sent Events give you a one-way event stream over ordinary HTTP. `res.sse()`
sets the headers a browser `EventSource` expects, and you write framed events into
the response.

## Problem

A dashboard or build log must push updates to a browser without a WebSocket
handshake or a polling loop. The stream may end, and the client must reconnect
cleanly.

## Assumptions

- Events are generated inside the handler. The SSE helper is synchronous; it has no
  timer and no producer callback.
- One open stream holds one connection slot for its lifetime.
- A proxy sits between the browser and the server, or will later.

## Send a finite stream

```zig src/main.zig
const std = @import("std");
const uz = @import("uWebZockets");

fn events(_: *uz.Request, res: *uz.Response) void {
    var stream = res.sse() catch |err| {
        std.log.err("sse start failed: {}", .{err});
        return;
    };

    stream.send_event("tick", "one") catch return;
    stream.heartbeat() catch return;
    stream.send_event("tick", "two\nthree") catch return;
    stream.close() catch return;
}

pub fn main(init: std.process.Init) !void {
    var app = try uz.App(128).init(init.io);
    defer app.deinit();

    _ = try app.get("/events", events);
    try app.catch_shutdown_signals();
    try app.listen("127.0.0.1", 3000);
    try app.run();
}
```

The handler writes the sequence and closes before it returns. If it returns with
the stream still open, the transport flushes what it has and closes the connection.

## Framing

| Input                    | Written                                  |
| ------------------------ | ---------------------------------------- |
| `event` non-empty        | One `event: NAME` line                   |
| Each `\n`-separated line | One `data: LINE` line                    |
| Always                   | One blank line after the last data field |
| `heartbeat()`            | `: keep-alive` and a blank line          |

A trailing `\r` is removed before framing, so CRLF input produces the same fields
as LF input. A CR or LF in the event name returns `error.InvalidEventName` before
any field for that event is written.

```console
event: tick
data: two
data: three

: keep-alive

```

## Proxy behavior

`sse()` sends `Content-Type: text/event-stream`, `Cache-Control: no-cache`, and
`X-Accel-Buffering: no`. The last field asks nginx-style proxies not to buffer; it
is a request, not a guarantee.

- Disable response buffering for this route in the proxy configuration.
- Set the proxy read timeout longer than the heartbeat interval.
- Send a heartbeat more often than the shortest idle timeout on the path.
- Keep compression off for event streams; a compressing proxy can hold bytes.

## Capacity assumptions

| Resource           | Bound                                                                       |
| ------------------ | --------------------------------------------------------------------------- |
| Write queue        | 64 KiB per connection; a field that does not fit returns `error.WouldBlock` |
| Total stream size  | No cap; the queue bounds one write, not the stream                          |
| Connections        | Each open stream holds one slot of `max_clients`                            |
| Heartbeat interval | Shorter than every proxy and client idle timeout                            |

SSE on HTTP/1.1 uses chunked transfer coding. HTTP/2 and HTTP/3 carry the same
field bytes in `DATA` frames with no chunk framing.

## Failure behavior

| Condition                            | Result                                          |
| ------------------------------------ | ----------------------------------------------- |
| Event name contains CR or LF         | `error.InvalidEventName`; earlier fields remain |
| Write queue full                     | `error.WouldBlock`; the event is incomplete     |
| Write after `close()`                | `error.ResponseNotStreaming`                    |
| `sse()` after another helper started | `error.ResponseAlreadyStarted`                  |
| Method or status forbids a body      | `error.BodyNotAllowed`                          |
| Peer or transport already closing    | `error.ConnectionClosed`                        |

A write error cannot become a different status, because the response head is
already sent. Return from the handler and let the transport close the stream.

## Verification

```sh
curl -N -i http://127.0.0.1:3000/events
curl -sN http://127.0.0.1:3000/events | grep -c '^event: tick'
```

`-N` disables curl buffering. Expect `200 OK`, `Content-Type: text/event-stream`,
`Cache-Control: no-cache`, and `X-Accel-Buffering: no`, then both events and the
heartbeat comment. The count is `2`, which works as a pass/fail check.

## Variation: a periodic producer

The helper cannot wait between writes, so the period must come from the client.
Emit a bounded window per request and have the client ask for the next one.

```zig
fn window(req: *uz.Request, res: *uz.Response) void {
    const query = req.query_params() catch {
        res.end("400 Bad Request", "") catch {};
        return;
    };
    const from = (query.get_int(u64, "from") catch null) orelse 0;
    var stream = res.sse() catch return;

    var seq = from;
    while (seq < from + 3) : (seq += 1) {
        var buffer: [48]u8 = undefined;
        const payload = std.fmt.bufPrint(&buffer, "{{\"seq\":{d}}}", .{seq}) catch return;
        stream.send_event("tick", payload) catch return;
        if (seq + 1 < from + 3) stream.heartbeat() catch return;
    }
    stream.close() catch return;
}
```

The cursor travels in the query string. When the stream closes, the client opens
`/events?from=<next>`; a bare `EventSource` reconnect repeats the same URL and would
replay the same window. The helper emits no `retry:` field, so the client also
decides the delay.

## Variation: plan for reconnects

`EventSource` reconnects automatically, but the helper writes no `id:` field, so
the client has no `Last-Event-ID` to resume from. Treat every connection as a new
subscription:

- Put an application sequence in `data` and let the client send its last position.
- Re-fetch a snapshot when the sequence has a gap.
- Deduplicate events the application can deliver twice.
- Do not invent SSE fields the helper does not write.
