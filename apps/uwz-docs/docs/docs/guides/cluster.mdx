A cluster is several independent applications on one port. Each worker owns its
loop, slab, connection slots, and TLS context; the kernel distributes accepted
connections.

## Problem

One core leaves the others idle. You want thread-per-core scaling without shared
request state, and you need to name the worker that failed.

## Assumptions

- The host is Linux or macOS; Linux pins workers to physical cores.
- `SO_REUSEPORT` is available. Windows uses `SO_REUSEADDR` with an unspecified
  distribution.
- Worker count fits the physical cores you intend to use.
- HTTP/3 is not clustered; QUIC stays single-application.

## Write the program

```zig src/main.zig
const std = @import("std");
const uz = @import("uWebZockets");

fn hello(_: *uz.Request, res: *uz.Response) void {
    res.text("hello from a worker") catch |err| std.log.err("response failed: {}", .{err});
}

pub fn main(init: std.process.Init) !void {
    var group = try uz.Server.builder(init.io)
        .with_max_clients(256)
        .with_write_queue_size(32 * 1024)
        .build_cluster(std.heap.page_allocator, 4, .{});
    defer group.deinit();

    const Cluster = @TypeOf(group);
    try group.configure(struct {
        fn routes(worker: *Cluster.Worker, index: usize) !void {
            _ = index;
            _ = try worker.get("/", hello);
        }
    }.routes);

    try group.catch_shutdown_signals();
    try group.listen("0.0.0.0", 3000);
    group.run() catch |err| {
        if (group.first_failure()) |failure| {
            std.log.err("worker {d} ({s}): {s}", .{
                failure.index,
                @tagName(failure.phase),
                @errorName(failure.err),
            });
        }
        return err;
    };
}
```

`build_cluster` takes the allocator, the compiled worker capacity, and
`ClusterOptions`. Every active worker registers the same routes through
`configure` before any thread starts. Each worker then binds the same port and
accepts independently.

## Verify it

```sh
zig build run
```

```sh
curl -s http://127.0.0.1:3000/
```

Expect `hello from a worker`. Repeat it: the kernel balances new connections
across the listening sockets. One TCP connection stays on the worker that
accepted it, so a keep-alive client measures one core, not the group.

```sh
kill -TERM "$(pgrep -f 'zig-out/bin/your-app')"
```

`catch_shutdown_signals` drains every worker; `run` joins them and `deinit`
releases the slabs.

## Worker capacity and active count

| Call                          | Reports                                           |
| ----------------------------- | ------------------------------------------------- |
| `worker_capacity()`           | Compiled capacity from `build_cluster`            |
| `worker_count()`              | Active workers that allocate a loop and slab      |
| `ClusterOptions.worker_count` | Explicit active count below the compiled capacity |
| `UWEBZOCKETS_WORKERS`         | Environment override for the environment builder  |

A count above the physical core count wraps over the selected cores.

## Publish across workers

WebSocket pub/sub is per worker by default. `Cluster.publish` broadcasts through
one bounded inbox per worker and wakes each loop:

```zig
const report = group.publish_report("chat", "hello workers", true) catch |err| {
    std.log.err("publish failed: {}", .{err});
    return;
};
if (!report.all_delivered()) {
    std.log.warn("queued={d} dropped={d} notify_failed={d} first={?d}", .{
        report.queued,
        report.dropped,
        report.notify_failed,
        report.first_dropped_worker,
    });
}
```

`publish` returns the queued count; `publish_report` names dropped inboxes and
failed wakeups. Delivery is queue delivery, not application subscription. A
stopped group returns `error.ClusterStopped`.

## Capacity assumptions

| Resource             | Bound                    | Consequence                     |
| -------------------- | ------------------------ | ------------------------------- |
| Cross-worker message | Bounded inbox per worker | Full inbox increments `dropped` |
| Slab                 | One per active worker    | Worker count multiplies memory  |

## Failure behavior

| Phase     | Cause                                 |
| --------- | ------------------------------------- |
| `spawn`   | A worker thread could not start       |
| `run`     | A worker event loop returned an error |
| `cleanup` | A post-run drain failed               |

The first failure wins, so a shutdown cascade does not replace the root cause.
`first_failure()` reports the worker index, phase, and original error;
`failure_count()` counts failures since the last `run`.

## Variations

### Read the worker count from the environment

```zig
var group = try uz.Server.builder(init.io)
    .build_cluster_from_environment(std.heap.page_allocator, 8, init.environ_map, .{});
```

The compiled capacity is 8, and the active count resolves in this order:
`ClusterOptions.worker_count`, `UWEBZOCKETS_WORKERS`, then the platform CPU
count. An invalid, zero, or above-capacity value fails before any slab exists.

```sh
UWEBZOCKETS_WORKERS=2 zig build run
```

### Terminate TLS in every worker

```zig
try group.enable_https("certs/fullchain.pem", "certs/privkey.pem");
try group.catch_shutdown_signals();
try group.listen("0.0.0.0", 8443);
try group.run();
```

Call `enable_https` once after `configure` and before `listen`. Each worker
owns one TLS 1.3 context and reads the PEM files once, so rotation is a rolling
restart. It does not configure client certificates.
