This page installs everything needed to build and run the tutorials. Choose one
path:

- Use Nix for a repository checkout with the pinned toolchain.
- Use a plain Zig 0.16.0 installation for the checkout.
- Add µWebZockets as a package dependency in your own project.

## Prerequisites

| Requirement     | Details                                                                               |
| --------------- | ------------------------------------------------------------------------------------- |
| Zig             | 0.16.0 exactly. Check with `zig version`.                                             |
| Host            | Linux or macOS on `x86_64` or `aarch64`. Windows has native compile and runtime jobs. |
| Nix             | Optional. The flake pins Nixpkgs 26.05 and Zig 0.16.0.                                |
| C/C++ toolchain | Not required separately. Zig compiles the pinned dependency sources.                  |

The first build fetches zslay, libxev, BoringSSL, lsquic, ls-qpack, ls-hpack,
libdeflate, and zlib through Zig's package manager. Later builds reuse the
global and local caches. No CMake, Ninja, Go, Perl, Python, `patch`, or system
zlib is required.

## Use Nix with a checkout

```sh
git clone https://github.com/farbenbuilds/uWebZockets.git
cd uWebZockets
nix develop
zig build hello_world -Doptimize=ReleaseSafe
```

Add `--recurse-submodules` to the clone only when you plan to run the h1spec
compliance suite. The `vendor/h1spec` submodule is not needed to build or use
the package.

In another terminal, verify the server:

```sh
curl -i http://127.0.0.1:3000/
```

The response is `HTTP/1.1 200 OK` and the body
`Hello from µWebZockets! Zero allocation achieved.`

## Use plain Zig with a checkout

Install Zig 0.16.0, then run the same repository commands without `nix develop`:

```sh
git clone https://github.com/farbenbuilds/uWebZockets.git
cd uWebZockets
zig build test --summary all
zig build -Doptimize=ReleaseSafe
```

`zig build -Doptimize=ReleaseSafe` builds the install graph. Individual example
steps are listed in the [examples tour](/docs/getting-started/examples-tour).

## Add the package to your project

Fetch a released tag or a full commit. Do not use a moving branch if you need
reproducible dependency resolution.

```sh
zig fetch --save 'git+https://github.com/farbenbuilds/uWebZockets#VERSION_OR_COMMIT'
```

Replace `VERSION_OR_COMMIT` with a release tag such as `v2.1.6`, or with a full
commit hash. The command adds the package to `build.zig.zon` under the
`uWebZockets` name.

Wire the module in `build.zig`:

```zig
const uz = b.dependency("uWebZockets", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("uWebZockets", uz.module("uWebZockets"));
```

A complete consumer program is in the [quickstart](/docs/getting-started/quickstart).

### Package-consumer expectations

- The package exports one module named `uWebZockets`.
- The module carries its native link metadata and dependency ordering, so a
  consumer does not link BoringSSL, lsquic, zlib, or libdeflate by hand.
- Consumers do not need the h1spec submodule, the repository examples, or the
  Nix flake.
- Releases are source tags. There are no per-platform binary archives, so the
  local Zig toolchain compiles the pinned dependencies on first use.
- The `tests/package_consumer` fixture compiles the documented quickstart
  against the module surface in CI.

## First-build cost and offline use

The first build is slower because Zig compiles BoringSSL, lsquic, libdeflate,
and zlib from source. Expect several minutes on a laptop and longer on a shared
CI runner. Later builds reuse `~/.cache/zig` and the project-local cache.

To build without network access, populate both caches on a connected machine
first, then reuse them. The dependency URLs and hashes are pinned in
`build.zig.zon`; Zig verifies the hashes when it unpacks a package.

## Verify the installation

Run the unit suite from the checkout:

```sh
zig build test --summary all
```

Run the hello-world example:

```sh
zig build hello_world -Doptimize=ReleaseSafe
```

If both commands exit with status 0, the toolchain, dependency cache, and native
build graph are ready.

## Common first-run problems

| Symptom                                   | Cause and fix                                                                                                          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `error: invalid Zig version`              | The active compiler is not 0.16.0. Run `zig version` and select 0.16.0.                                                |
| A dependency hash mismatch                | The package cache is corrupt or a URL changed. Remove the cached package and fetch again. Do not edit the pinned hash. |
| `error: FileNotFound` for `vendor/h1spec` | You ran a compliance step without the submodule. Clone with `--recurse-submodules` or skip that step.                  |
| The first build appears to hang           | It is compiling vendored C and C++ sources. Check CPU and disk activity before interrupting.                           |
| `curl: (7) Failed to connect`             | The server is not running, or it bound a different port. Check the terminal output.                                    |
