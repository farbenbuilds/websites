This page installs Zig and adds µWebZockets to your own project.

## Prerequisites

| Requirement     | Details                                                                               |
| --------------- | ------------------------------------------------------------------------------------- |
| Zig             | 0.16.0 exactly. Check with `zig version`.                                             |
| Host            | Linux or macOS on `x86_64` or `aarch64`. Windows has native compile and runtime jobs. |
| Network         | Zig downloads the pinned dependency sources on the first build.                       |
| C/C++ toolchain | Not required separately. Zig compiles the pinned dependency sources.                  |

## Download Zig

Download Zig 0.16.0 from [ziglang.org/download](https://ziglang.org/download/)
and put `zig` on your `PATH`. Verify the version:

```sh
zig version
```

```text
0.16.0
```

## Add the package

From the root of your own project, fetch the pinned release:

```sh
zig fetch --save 'https://github.com/farbenbuilds/uWebZockets/archive/refs/tags/v2.1.6.tar.gz'
```

The command adds the package to `build.zig.zon` under the `uWebZockets` name.
Use the same URL when you upgrade so the dependency stays reproducible.

## Wire the module

Add the module to your executable in `build.zig`:

```zig
const uz = b.dependency("uWebZockets", .{
    .target = target,
    .optimize = optimize,
});
exe.root_module.addImport("uWebZockets", uz.module("uWebZockets"));
```

A complete consumer program is in the [quickstart](/docs/getting-started/quickstart).

## Package expectations

- The package exports one module named `uWebZockets`.
- The module carries its native link metadata and dependency ordering, so you do
  not link BoringSSL, lsquic, zlib, or libdeflate by hand.
- Releases are source archives. There are no per-platform binary archives, so
  Zig compiles the pinned dependencies on first use.

## First build and offline use

The first build is slower because Zig compiles BoringSSL, lsquic, libdeflate,
and zlib from source. Later builds reuse `~/.cache/zig` and the project-local
cache.

To build without network access, populate both caches on a connected machine
first, then reuse them. The dependency URL and hash are pinned in
`build.zig.zon`; Zig verifies the hash when it unpacks a package.

## Verify the install

Add the server from [Quickstart](/docs/getting-started/quickstart), then run:

```sh
zig build run
```

The development log prints the version, startup time, and local address. Stop
the server with Ctrl+C.

## Common first-run problems

| Symptom                         | Cause and fix                                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `error: invalid Zig version`    | The active compiler is not 0.16.0. Download Zig 0.16.0 and select it.                                                    |
| A dependency hash mismatch      | The package cache is corrupt or the URL changed. Remove the cached package and fetch again. Do not edit the pinned hash. |
| The first build appears to hang | It is compiling vendored C and C++ sources. Check CPU and disk activity before interrupting.                             |
| A dependency download fails     | Check network access to GitHub, then run the same `zig fetch` command again.                                             |
