The pages in this section can be read in order, but most readers arrive with a
specific job. Pick the path that matches your goal.

## Evaluate the framework

Read these pages before committing to a prototype:

1. [What is uWebZockets](/docs/what-is-uwebsockets)
2. [Why uWebZockets](/docs/why-uwebsockets)
3. [Motivation](/docs/getting-started/motivation)
4. [FAQ](/docs/getting-started/faq)

You should be able to answer three questions: does the bounded model fit the
workload, does the protocol surface cover the service, and are the unsupported
features acceptable?

## Build the first server

This is the shortest path to a running process:

1. [Installation](/docs/getting-started/installation)
2. [Quickstart](/docs/getting-started/quickstart)
3. [Your first HTTP server](/docs/getting-started/first-http-server)
4. [Project structure](/docs/getting-started/project-structure)

Then choose the next surface:

- Realtime: [Your first WebSocket](/docs/getting-started/first-websocket)
- Typed APIs: [Your first JSON-RPC service](/docs/getting-started/first-json-rpc-service)
- HTTPS: [Your first TLS server](/docs/getting-started/first-tls-server)
- Multi-core: [Your first cluster](/docs/getting-started/first-cluster)
- QUIC: [Your first HTTP/3 server](/docs/getting-started/first-http3-server)
