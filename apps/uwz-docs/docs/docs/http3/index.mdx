`init_http3` creates two TLS contexts: TCP advertises `h2` and `http/1.1`, and
QUIC advertises `h3`. The same routes serve all three. This section documents the
live HTTP/3 request path, its QUIC policy, and the boundaries that keep
WebTransport out of the supported surface.

The live path is a bounded request/response server. It is not a general-purpose
QUIC platform, and it does not share every HTTP/1.1 operational feature. The
canonical program is the [HTTP/3 server example](/examples/http3-server).

## Startup

```zig
var server = try uz.App(128).init_http3_ephemeral(init.io);
defer server.deinit();

_ = try server.get("/", index);
try server.listen_udp("0.0.0.0", 8443);
try server.catch_shutdown_signals();
try server.run();
```

The `App` value must stay at a stable address after `listen_udp`; the QUIC engine
holds a pointer to it. Do not move it into a container that reallocates.

| Listener     | Protocol                                |
| ------------ | --------------------------------------- |
| `listen`     | TCP with TLS, ALPN `h2` then `http/1.1` |
| `listen_udp` | QUIC, ALPN `h3` only                    |

## Boundaries

| Feature                    | Status                                       |
| -------------------------- | -------------------------------------------- |
| HTTP/3 request routing     | Supported                                    |
| 0-RTT                      | Not supported; rejected on the live listener |
| HTTP/3 clustering          | Not supported                                |
| Metrics registry           | Not advanced; development log only           |
| WebTransport live path     | Not supported; CONNECT answered with `501`   |
| WebTransport helper models | Helper-only, draft-16                        |
| QUIC client                | Not shipped                                  |

:::warning[WebTransport is not live]
`uz.webtransport` and `uz.http3_extensions` exist, but the live lsquic listener
is not connected to them. A CONNECT request receives `501 Not Implemented`. Do not
describe WebTransport as a supported transport on this version.
:::
