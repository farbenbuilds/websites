Operations covers two different jobs. Some pages explain how to change, verify,
and release the µWebZockets repository itself; those are contribution guides for
[farbenbuilds/uWebZockets](https://github.com/farbenbuilds/uWebZockets). Other
pages explain how to run an application that installed the package with
`zig fetch --save`.

Do not run a framework-contributor command against an application project. The
build graphs differ: the framework checkout owns `builds/`, its test steps, and
its release scripts; a consumer project owns its `build.zig`, pins the package in
`build.zig.zon`, and imports the public `uWebZockets` module.

## Contribute to µWebZockets

These pages assume a clone of
[farbenbuilds/uWebZockets](https://github.com/farbenbuilds/uWebZockets). They are
not application build steps. Use them when you change the framework, reproduce a
maintainer gate, or prepare a pull request against the original repository. The
repository's own
[CONTRIBUTE.md](https://github.com/farbenbuilds/uWebZockets/blob/main/CONTRIBUTE.md)
owns the branch and review process.

## Advanced surfaces for applications

These pages are application features, not framework build steps. They assume the
package was added with `zig fetch --save`; each page shows the consumer
`build.zig` wiring or public module import you need.

<CardGroup cols={2}>
  <Card title="WASM edge targets" href="/docs/operations/wasm" icon="cpu">
    Build the freestanding or WASI edge module from the dependency and call its bounded exports.
  </Card>
  <Card title="eBPF latency histogram" href="/docs/operations/ebpf" icon="activity">
    Compile the XDP objects in your application, pin the latency map, and read its packet buckets.
  </Card>
  <Card title="kTLS" href="/docs/operations/ktls" icon="key-round">
    Import `uz.ktls` and program kernel TLS record state on a socket your application already owns.
  </Card>
  <Card title="AF_XDP" href="/docs/operations/af-xdp" icon="network">
    Import `uz.xdp_transport` and `uz.xdp`, compile the redirect, and drive the rings from your
    process.
  </Card>
</CardGroup>

| Surface | After `zig fetch --save`                                          | Public entry point           |
| ------- | ----------------------------------------------------------------- | ---------------------------- |
| WASM    | Resolve a `wasm32` target in `build.zig` and install the artifact | The dependency artifact      |
| eBPF    | Compile the package C sources with your own `build.zig` step      | `uz.ebpf`                    |
| kTLS    | Import the module; no extra build step                            | `uz.ktls`                    |
| AF_XDP  | Compile the redirect and import the transport                     | `uz.xdp`, `uz.xdp_transport` |

## What the section assumes

| Assumption                | Detail                                                                                                                            |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Compiler                  | Zig 0.16.0. The Nix shell provides it; a plain install must match the minor version.                                              |
| Host platforms            | Linux runs the hosted matrix on `x86_64` and `aarch64`. macOS is supported and cross-compiled; Windows is gated by a runtime job. |
| Repository access         | The contributor pages use a clone of `farbenbuilds/uWebZockets`; application pages use `zig fetch --save`.                        |
| Network on the first run  | Zig fetches the pinned dependency packages into its global and local caches.                                                      |
| No system build toolchain | BoringSSL, lsquic, ls-qpack, ls-hpack, libdeflate, and zlib are compiled from pinned sources.                                     |
