This section is for maintainers and contributors who build and verify
µWebZockets itself: the framework repository, its pinned dependencies, its test
gates, and its release and runtime work. If you are adding µWebZockets to an
application, start with [Installation](/docs/getting-started/installation)
instead. That page uses `zig fetch --save`; this section starts from a clone of
the framework.

The pages here describe commands that operate on the framework checkout. They
are not application build steps, and they are not required to use the package.

## How the section is organized

| Group    | Question it answers                                                      |
| -------- | ------------------------------------------------------------------------ |

## What this section assumes

| Assumption                | Detail                                                                                                                            |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Compiler                  | Zig 0.16.0. The Nix shell provides it; a plain install must match the minor version.                                              |
| Host platforms            | Linux runs the hosted matrix on `x86_64` and `aarch64`. macOS is supported and cross-compiled; Windows is gated by a runtime job. |
| Repository access         | A clone of `farbenbuilds/uWebZockets`, plus the `vendor/h1spec` submodule for the h1spec gate.                                    |
| Network on the first run  | Zig fetches the pinned dependency packages into its global and local caches.                                                      |
| No system build toolchain | BoringSSL, lsquic, ls-qpack, ls-hpack, libdeflate, and zlib are compiled from pinned sources.                                     |
